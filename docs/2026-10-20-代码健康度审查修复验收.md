# 代码健康度审查修复验收

对应审查基线为 `d2cb85f`，本轮核对三个阶段的工程改动，不把自动测试替代为真实麦克风、云端接口或真实大模型推理验收。

## 第一阶段：录音与本地服务边界

- 事件 tap 重建保留活动 hold/toggle 和计时器；ASR 提前关流进入处理态并保留热键占用。
- 本地服务只继承白名单环境；SenseVoice 只接受固定文件清单、大小和 SHA256 验证通过的本地模型，不回退 ModelScope，关闭远程代码执行并启用离线模式。
- Qwen 无 ASR 模型时 `/transcribe` 返回 503；两套服务共享未闭合 `<think>` 截断处理。

最初提交为 `9081276`。

## 第二阶段：异步身份、上传与持久化

- 上传队列限 64 块、每次发送限 5 秒；队列溢出和 drain 超时都标记失败并只通知一次中断，停止后的完整音频恢复可感知该失败。
- UI 在创建录音请求时分配 UUID，并随会话事件传递；单一事件消费者按顺序更新 UI。取消、开始新录音或终态使旧 UUID 失效，不依赖两个单独 MainActor Task 的执行先后。
- LLM provider 在挂起前捕获，配置加载显式使用该 provider，client/config 成对使用。
- 模型列表状态独立管理 generation。切换服务商、改凭据、重发或关页先使 generation 失效，忽略取消的旧成功与旧失败响应都不能回填。
- 两类流式解析器对正文格式异常明确报错；推理元数据容错，不丢弃同一分块中的正常正文。
- 支持目录 0700，历史主库首次创建即 0600，WAL/SHM 与热词权限收紧；权限操作使用不跟随符号链接的文件描述符。

最初提交为 `aa713dc`；本轮复核补齐配置层的显式 provider、模型列表代际、上传 drain 失败与 UI 请求 UUID。

## 第三阶段：工程门禁与职责拆分

- `main` 要求 PR、实际 GitHub Actions `verify` 与 `local-service-boundary` 状态成功，管理员同样受约束，禁止强推/删除，讨论必须解决。
- 仓库协作者仅有所有者。PR 保留，额外他人批准数为 0；避免设置所有者不能自行完成的强制他人审核。后续修复通过正常 PR，不临时关闭保护绕过。
- 静态工具必须安装并执行；恢复全仓 SwiftLint，撤回仅检查最后一个提交的增量路径。浅克隆不再影响覆盖范围。
- SwiftLint 固定 0.65.0，并校验下载包 SHA256。旧基线已漂移，按补漏前提交 `3238ce0` 的实际代码重新记录历史债务，再对移动位置与既有巨型声明长度重新定位；最终固定 1,554 条历史违规。它们仍是债务，不能把全仓检查通过解释为没有风格或体积问题。新增模型列表状态与新测试的规范违规未加入豁免。
- Periphery 扫描失败会阻断，现有 unused 警告保留在日志，不批量删除通过反射、系统回调、测试或编解码使用的声明。
- macOS 本地服务任务从固定 SHA256 的官方 Sherpa 1.12.33 二进制及固定提交 C 头文件构造真实 xcframework，确认 SwiftPM 启用 binary target 后构建，再执行服务鉴权、模型清单、生命周期、服务解析和 bundle 打包回归。
- 从 `RecognitionSession` 拆出纯转写取值和恢复预算策略；从 Doubao 客户端拆出协议响应类型；设置页的模型列表异步状态成为独立对象。会话 actor 仍较大，后续应沿资源所有权继续渐进拆分。

## 验证与现场限制

本机及 GitHub 最终测试、构建、静态检查与同签名部署结果记录在本地 `REPAIR_PLAN.md` 完成记录中，远程 PR 与 CI 提供可查证日志。

本地服务边界使用受控模型夹具；没有下载或推理真实大模型，也没有新增真实麦克风、物理按键或第三方输入框验收。旧 CI 的取消、静态失败记录保留，没有将失败改写为通过。旧安装包版本号不变，本次通过 `MuseSourceCommit` 区分来源；未创建新的公开 Release。
