## 1. 测试目标

这套测试集用于判断 Dal 能否把真实口述草稿整理成“用户看一眼就敢直接发送”的文字。

北极星指标是**直接发送率**，不是模型请求成功率、Validator 通过率或是否返回了非空文字。

每条样本同时检查三件事：

1. 是否理解用户最终想表达什么，包括改口、补充、放弃和顺序调整。
2. 是否把口语草稿整理成符合当前场景的文字成稿。
3. 是否保留用户的事实、态度、表达力度和个人声音。

## 2. V1.2 范围

V1.2 包含两层输入：

- 40 条独立人工编写的场景基准样本，每个场景 5 条。
- 37 条“脏口述 / 脏 ASR”专项变体，与基准样本共享最终意图和参考成稿，其中含 9 条口吃专项样本。

总计需要执行 77 次输入。专项变体的作用不是增加新的写作任务，而是控制变量：同一个最终意图分别加入重复、口吃、口误、错误标点或错误断句，从而判断具体是哪一类输入问题导致润色失败。

| 场景 | 数量 | 主要用途 |
|---|---:|---|
| 私人聊天 `chat` | 5 | 短消息、问句、邀约、情绪和轻量列点 |
| 工作沟通 `workChat` | 5 | 进度、请求、决策、风险和复杂改口 |
| 邮件 `email` | 5 | 跟进、致歉、合同事实和多主题长邮件 |
| 文档与笔记 `documentNote` | 5 | 灵感、纪要、需求、复盘和不确定信息 |
| AI Prompt `aiPrompt` | 5 | 图片、代码、调研、文案和数据任务指令 |
| 社交内容 `socialPost` | 5 | 朋友圈、观点、口播、经验分享和公开纠错 |
| 技术表达 `code` | 5 | Bug、代码审查、部署步骤、架构和未知版本 |
| 客服沟通 `customerSupport` | 5 | 投诉、退款、预约、解释和回复草稿 |

这些样本同时覆盖现有盲测要求的八类难点：`proper_noun`、`self_correction`、`aside`、`disordered`、`list`、`numbers`、`mixed_language`、`ai_prompt`。

### 2.1 常见脏输入因素

| 因素 | 专项变体覆盖数 |
|---|---:|
| 无意义语气词/口头禅 | 5 |
| 字词连续重复 | 4 |
| 同义反复表达 | 5 |
| 即时或延迟改口 | 7 |
| 说到一半重新开头 | 6 |
| 未说完的半句话 | 3 |
| 整段缺少标点 | 12 |
| 标点位置错误 | 11 |
| 句子边界错误 | 12 |
| 内容顺序混乱 | 3 |
| 明确排除的旁注 | 3 |
| 不得进入正文的写法指令 | 3 |
| 专名同音近音识别错误 | 2 |
| 数字、时间、版本或范围改口 | 5 |
| 列表数量中途增加或减少 | 2 |
| 中英文/代码标识符错误分词 | 5 |
| 中文、数字或英文内部误空格 | 4 |
| “这个/那个/它”等模糊指代 | 3 |
| 斜杠、点、短横线等口述符号 | 2 |
| 口吃导致的重复字、重复词和序号起步 | 9 |

`factor_coverage_requirements` 固化了以上最低数量。后续删除或修改变体时，如果任一因素低于门槛，测试集完整性校验必须失败。

每种因素还在 `factor_acceptance_rules` 中定义了独立验收规则。例如：错误标点必须重新判断而不是机械沿用；机械重复要合并，但承担强调作用的重复不能全部删除；普通口误只保留最终版本，但公开纠错和改约场景必须保留必要的旧事实背景。

### 2.2 口吃专项

口吃不能简单并入普通“重复表达”。普通重复有时是在主动强调观点；口吃重复通常表现为说话起步时非自愿地反复某个字、音节、词语或序号。V1.2 单独覆盖四种形态：

| 口吃形态 | 示例 | 覆盖数 |
|---|---|---:|
| 单字或词内音节重复 | “我我我”“突突然” | 2 |
| 完整词语或短语重复 | “今天今天”“帮我帮我” | 3 |
| 多种口吃混合出现 | 同一句同时出现字、音节和词语重复 | 3 |
| 列表序号起步重复 | “第第一”“第第二” | 1 |

验收要求是删除非自愿的起步重复和卡顿残片，同时保留真正的强调、并列和有意重复。例如“功能越来越多”“一直在改、一直在补”不能因为表面出现相近表达就被机械删掉。

还要区分两个处理层级：

- **说话者真实口吃**：属于语音润色输入，应由润色恢复成自然、完整的文字。
- **流式 ASR 拼接重复**：如果同一段 partial 结果被系统重复追加，属于识别链路缺陷，应在流式合并阶段修复，不能把润色模型当成唯一兜底。

执行完整性校验：

```bash
python3 scripts/validate-voice-polish-quality-test-set.py
```

## 3. 字段说明

每条样本包含：

- `spoken_input`：模拟 ASR 得到的真实口述终稿，不刻意写成规范文章。
- `preconditions`：仅在需要已确认术语等前置条件时出现；试跑前必须满足。
- `stress_variants`：共享基准样本意图与参考成稿的脏输入变体。
- `input_factors`：该变体明确注入的问题类型；必须来自 `input_factor_definitions`。
- `stutter_form`：口吃专项变体的具体形态；非口吃变体不得使用该字段。
- `factor_acceptance_rules`：每类脏输入分别怎样处理才算通过。
- `reference_output`：人工参考成稿，只用于表达正确语义与质量下限，不做逐字匹配。
- `must_preserve`：输出中必须保留的事实、意图、态度或表达力度。
- `must_remove`：必须从正文中清掉的口误过程、机械重复或已放弃内容。
- `must_not_invent`：模型不得自行补充的事实、承诺、原因或结论。
- `format_expectation`：最低结构要求。
- `tone_expectation`：场景需要的语气。
- `acceptable_variations`：允许与参考成稿不同的范围。
- `evaluation_focus`：本条最重要的人工检查点。

## 4. 评分方法

### 4.1 硬门槛

以下任一项失败，本条直接判为“不可用”：

- 改变用户最终意图或问答类型。
- 丢失、改错或编造关键事实、数字、时间、专名。
- 保留已经明确放弃的旧版本。
- 回答或执行 AI Prompt，而不是整理 Prompt 本身。
- 引入原文没有的承诺、原因、人物、结论或营销话术。

专项变体还必须逐项满足其 `input_factors` 对应的 `factor_acceptance_rules`。如果事实安全但仍保留明显错标点、错断句、机械重复或口误过程，不能评为 `direct_send`。

### 4.2 人工结论

每条只选一个：

| 结论 | 定义 |
|---|---|
| `direct_send` | 无需修改，愿意直接发送、粘贴或保存 |
| `minor_edit` | 事实正确，只需改一两个词或轻微标点 |
| `major_edit` | 需要重写句子、恢复语气、重排结构或补回遗漏 |
| `unusable` | 意图/事实错误、脑补、答非所问或基本退回原始草稿 |

安全回退原文通常应记为 `major_edit`；它只说明没有注入危险草稿，不代表润色成功。

### 4.3 建议发布门槛

- 关键事实、最终意图和白名单外实体幻觉：全部 77 次输入零失败。
- 40 条场景基准的 `direct_send` 不低于 85%。
- 37 条脏输入变体的 `direct_send` 不低于 85%。
- 9 条口吃专项变体必须全部正确去除非自愿重复，且不得误删有意强调。
- 两层输入各自的 `direct_send + minor_edit` 不低于 95%。
- 每一种 `input_factor` 都不得出现 `major_edit` 或 `unusable`。
- 每个场景 5 条中至少 4 条达到 `direct_send`。
- 不得用参考成稿逐字相似度代替人工判断。

## 5. 使用顺序

1. 先跑 40 条基准 `spoken_input`，再跑 37 条 `stress_variants.spoken_input`；专项变体沿用对应 `base_case_id` 的参考成稿和验收要求。
2. 冻结输出、模型、Prompt 版本、commit、耗时、路由、调用数和回退状态。
3. 先跑硬门槛检查，再由不知道实现细节的评审者做可发送性评分。
4. 同一基准意图下，比较基准输入与各脏输入变体：如果只有某类变体失败，就按 `input_factors` 定位能力缺口。
5. 失败时按场景、难点标签和人工原因归类，不围绕单条样本继续堆正则。
6. 文本母集通过后，再由真人按 `spoken_input` 自然录音，使用同一音频分别运行 Dal 与对照产品，接入现有盲测工具。

## 6. 当前边界

这是一套**产品质量文本母集**，用于先固定“测试什么、什么结果算好”。专项变体模拟了常见 ASR 文本错误，但仍不是现有 100 条真实同音频盲测的替代品，也不能完整代表真实噪声、口音和说话节奏差异。

后续录音时不要照稿逐字朗读，应保留自然停顿、重复、改口和补充，否则会把语音润色测试退化成普通文本改写测试。
