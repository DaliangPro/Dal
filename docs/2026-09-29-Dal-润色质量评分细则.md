# Dal 润色质量评分细则

日期：2026-09-29

本细则统一独立评审对润色输出的判读口径，供每轮验收与变体对照共用。验收门槛见[产品需求](2026-08-17-Dal-Voice-Polish-Product-Requirements.md)的「验收」一节；本文件只规定如何给单条输出定档。

## 定档

每条输出只给一个档位，依据是用户拿到后要不要改、改多少。

| 档位 | 含义 |
|---|---|
| direct_send | 可直接发送，无需任何修改。 |
| minor_edit | 事实与意图正确，只需删一句、调标点或排版等小改动。 |
| major_error | 事实、意图、实体或必须的结构有错，用户需要重写一部分或核对原话。 |
| unusable | 空输出、乱码、回退原文且原文不可用、回答或执行了语音中的任务。 |

另外单独标记三类关键错误，门槛均为 0：

- **关键事实错误**：丢失、篡改或写反数字、日期、时间限定词、金额、人名、专名、参与方、数量、否定、条件或待确认状态。
- **最终意图错误**：改变了谁做什么、要做还是不做、给谁的要求。
- **无来源实体错误**：出现原文与已授权上下文都没有的人名、专名或事实。

## 常见情形的固定判法

| 情形 | 档位 |
|---|---|
| 说给输入法的编辑要求残留在正文（“帮我整理成…”“这句别写太重”“发一条更正通知”），未改变意图 | minor_edit |
| 说给输入法的编辑要求被当成给收件人或 AI 的命令写进正文，改变了意图 | major_error，并标最终意图错误 |
| 给收件人或未来 AI 的要求（“请先别启动”“不要承诺今天修好”）被删掉 | major_error，并标关键事实错误 |
| 删编辑要求时连带删掉了只在该句出现的名称、主题或事实 | major_error，并标关键事实错误 |
| 改口过程原样残留（“A，不对，B”）或仍按旧说法写 | major_error |
| 原文说出了数量（两步、三件事、两个原因）的枚举未逐项换行 | major_error |
| 没说数量的“先…再…最后…”顺序要求未编号 | minor_edit |
| 有意强调的重复被压缩（“真的真的”→“真的”） | minor_edit |
| 口吃重复未清干净（“小小林”） | minor_edit |
| 断句别扭但不改意思 | minor_edit |
| 断句改变了谁做什么 | major_error，并标最终意图错误 |
| “跟客户说……”保留为对同事的交代、未替用户代答 | direct_send |
| 技术字面量（路径、命令、代码名）被加空格或拆开，不能直接复制使用 | minor_edit |
| 凭空增加列表项、建议或结论 | major_error，并标无来源实体错误 |

未列出的情形，按“用户需要改多少才能发”类推，并在理由中写明。

## 变体对照（配对判读）

比较两个提示词、参数或模型变体时，不分别给绝对档位，而是逐条并排阅读同一输入的两份输出：

1. 隐藏来源，随机决定左右位置。
2. 每条判为「A 更好 / B 更好 / 相当」，并写一句理由；关键错误按上表单独标注。
3. 汇总胜、平、负条数与双方关键错误数。只有变体胜多于负且关键错误不增加，才进入完整验收。

同一配置重复运行两次的差异视为模型波动基线；变体的净胜条数不超过该基线时，不认为有真实改进。

## 自动初筛

`scripts/voice-polish-autocheck.py` 检查改口残留、编辑指令残留、说出数量却未分项、日期与数字丢失等可客观判断的特征。它只用于变体初筛，漏检较多，不能替代逐条判读。
